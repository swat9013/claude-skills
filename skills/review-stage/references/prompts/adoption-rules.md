- 1 件ごとに impact scenario (どの入力・状態・変更を経て何に影響するかの道筋) を示す: 欠陥なら発生シナリオ、書き方なら「どの変更が、どこへ波及するか」、spec なら spec のどの行とどう食い違うか、設計なら設計 doc のどの保証・設計規則・境界・構造とどう食い違うか。impact scenario は道筋だけを 1〜2 文で書く (後段の区分が読むのは、道筋が読んで成り立つかだけ)。impact scenario を示せないものは報告しない
- Evidence は、「1 件ごとに次の行で書く」の項の Evidence の行と、報告の規則のうち Evidence に並べる箇所を名指す項が挙げる箇所だけを逐語で引く — 再レビューと反証は Evidence の引用で同じ箇所を照合するので、言い換えると照合が外れる。名指されていない前後の行は、後段が読む量だけを増やす
- 次は報告しない: 書き方の好みの違い (別の書き方もできる、だけのもの) / 起きるかもしれない、だけの仮説 / lint・型検査・gate が既に機械検証している事項
- 重要度で件数を絞らず、当てはまったものを全件出す (取捨は後段が行う)
- 入力を読み切って判定したときの報告の本文は、「1 件ごとに次の行で書く」の項の形で書いた指摘だけにする。指摘が無ければ `指摘なし` の 1 行だけを返す — 読んだ file や適用した規約の一覧・件数の要約・総括は、後段の区分に使われず、後段が読む量だけを増やす
