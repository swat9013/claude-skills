# 親が代行する merge

SKILL.md 手順 7 で、ユーザーが merge を頼んだときの手順。本書の `${CLAUDE_SKILL_DIR}` は SKILL.md と同じ skill ディレクトリを指す。

merge の前に `${CLAUDE_SKILL_DIR}/../review-stage/references/merge-check.md` を Read し (会話の圧縮や再開の後は読み直す)、頼まれた CL ごとに、head の SHA の控え・確かめ・問い直し・merge のコマンドをその手順に従って行う。その手順が人に返す・問う箇所は、この skill がユーザーに問う箇所として扱う。merge を始める前に、頼まれた順を `${CLAUDE_SKILL_DIR}/scripts/cl-plan.py check-merge-order <計画の記録> <頼まれた行の名前>... --done <CL が merged の行の名前>...` に通し、`violations` が出たら (merge されていない前段より先に後続を頼まれたとき) merge せず、`recommended` を推奨順として添えてユーザーに問う。頼まれた CL を SKILL.md 手順 6 の推奨順に 1 本ずつ merge する。GitHub は `--delete-branch` を付けない (head branch が merge で消えたときは SKILL.md 手順 7 の冒頭の段落に従う)。GitLab は MR に「source branch を削除」が付いていれば `glab mr update <番号> -R <CL の repo> --remove-source-branch` (付け外しを切り替える) で外してから merge する — source branch を消すと、後続の CL は close されうる。どの CL も (1 本目を含めて)、merge する前に状態を引き直し、SKILL.md 手順 7 の `cl-state.py classify` がその CL に `merge_ok` を true で出してからにする。1 本 merge するごとに SKILL.md 手順 7 の項を当ててから次へ進む — 付け替える前に後続を merge すると、変更は merged の前段 branch に入るだけで既定ブランチに届かないのに、CL は merged と表示される。親が CL エージェントへ頼んで増えた commit (指摘の修正・担当範囲への依頼・CL エージェント定義の手順 2 の通し直し) も、確かめの手順 `merge-check.md` の「依頼の後に増えた差分」の項目として merge せず問い直す。問い直した CL に依存しない残りの CL は推奨順のまま続ける
