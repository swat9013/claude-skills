# いつ自動化するか: 些細でない作業は道具で行い、規約の遵守と決定的な推論は機械に任せる

- **些細でない作業は道具で行う**: 些細でない作業 (編集・移行・分析・検査) は、反復の回数によらず道具 (codemod・script・generator・再実行できる検査) で行う — 道具は、レビュアーが再実行して同じ結果を確かめられる記録になり、手で行った結果は、差分は読めても、漏れと不揃いが無いかを再実行で確かめ直せない。些細とは、結果のすべてを読み手が目で見て確かめ切れる作業を指す (例: 明らかな編集が 2、3 個)。道具を省いてよいのは、些細な作業だけ。道具は CL の差分に載せ、merge 後に残すかは `principle-deletability` に従う。道具の大きさは `principle-least-code` に従う
- **遵守は機械で保証する**: 規約の遵守を人の注意力に頼らない。決定的に判定できる制約 (索引と本文のような記述の同期・層や範囲の境界を含む) は、既定で lint / hook / 型・構造で守らせる。誤検知が実害になるときだけ散文で守り、機械にしない理由を規約の側に 1 句で残す。遵守が難しい表現形式 (手書きの TAB 区切り等) は最初から選ばない
- **決定的にできる推論は script へ追い出す**: LLM 推論のうち決定論的に書ける部分は script 化する (テスト可能・トークン削減)。実現手段は非標準の拡張より標準機能内での実現を優先する — 標準機能は配布先にも既にあり、拡張の導入と追従が要らない。標準機能で書けないときだけ拡張を使う
