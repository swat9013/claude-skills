# 親子の関係の記録

子 issue を親 issue に結ぶ手順。どの issue を親にするか・止めたときの宛先は呼び出し元の手順が決め、本書は記録の仕方だけを持つ。コマンドは対象 repo の `docs/agents/issue-tracker.md` の CLI 規約に従い、規約が無ければ GitHub (`gh`) の綴りの例を tracker の綴りへ読み替える。

## 結び方

- **tracker の親子の関連で記録する。** GitHub の sub-issue なら、既にある子は `gh issue edit <親> -R <issue 置き場> --add-sub-issue <子>` で結び、子を作るときに結ぶなら `gh issue create -R <issue 置き場> --parent <親> ...` で作る
- **関連を持たない tracker では本文で記録する。** 親の本文の task list に子の行 (`- [ ] #<子>`) を足し、子の本文の先頭に `Part of #<親>` を置く。親の本文に行を足すのは本文の書き換えなので、`body-rewrite.md` の基準の保存・open CL の確かめ・書き戻しを通す (行を足すだけなら、同書の手順 4 の例外に当たる)。既に本文を持つ子の先頭に `Part of #<親>` を足すときは、旧本文の記録まで含めて `body-rewrite.md` のとおりに書き換える。子を作る本文に初めから `Part of #<親>` を入れるなら、書き換えにならない
- **子を作った手段が親を記録しなかったら、その手段を呼んだ側が本書で記録する。** 外の skill や tool が子だけを作って親を変えないことがあり、記録しないと親から子へ辿れない

## issue を子に分けたとき

skill の手順が issue を子に分けたときは、その操作の中で、子を 1 つ以上親に結べた後に親へ `tracking-issue` を付ける — 先に付けると、子の作成か記録で止まったときに子を持たない `tracking-issue` の親が残る。対象 repo に `tracking-issue` に当たる label が無ければ付けず、付けなかったことを宛先へ返す報告に書く。付けた `tracking-issue` は外さない。親の状態の label は分けた時点のまま変えない — `tracking-issue` は親を直接の実装と triage から外す印で、外すと親が子と重ねて実装されうる。

## 失敗したとき

関連の記録か本文の書き換えが失敗したら、親と子の番号、記録できた分とできなかった分を、呼び出し元の手順が決めた宛先へ渡す。本文の書き換えで止めたときの扱いは `body-rewrite.md` の「停止の扱い」に従う。
