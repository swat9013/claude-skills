# 完了を宣言する前に実物で確かめる

- **検証対象は実物にする**。ビルドが通った・タイムスタンプが新しい・キャッシュにある、といった代理指標で完了を判断しない
- **経路を端から端まで通す**: 実装した機能を実際の使われ方どおりに動かし、入力から出力までデータが流れることを確かめる
- **委譲した作業は成果物で受け取る**。エージェントの報告文ではなく、生成された差分・ファイルの中身・実行時の挙動を自分で見る (報告は意図であって結果ではない)
- **観測方法を疑ってよいのは条件付き**: その検証経路を一度も通したことがない、または系側に変更が無いのに落ちた場合に限り、観測側を 1 度だけ確かめる。それ以外は系の欠陥として扱う (`swat-skills:principle-fix-root-causes`)
- **同じ検証を繰り返すなら決定的な script にする**。他者が再実行できる形は一度きりの目視より強い (自動化する時期の判断は `swat-skills:principle-automate-when-it-hurts`)

合格線そのものの判定は `swat-skills:principle-review-ready-bar` が扱う。本原則は**合格を主張する前に何を根拠に置くか**を決める。
