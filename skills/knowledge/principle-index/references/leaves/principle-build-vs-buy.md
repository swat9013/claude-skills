# 既製品を既定にし、選定はテスト・可読性・簡単さで切る

- **自前実装と既製品が拮抗したら既製品を選ぶ** (build vs buy)。自前は作り込むほど柔軟性と操作の直感性を失う。自前を選ぶなら「既製品では満たせない要件」を先に言語化する
- **自前化と fork は上流更新への追従コストを買う**。既製品を fork して手を入れる・確立した仕組み (プロビジョニング・実行環境・配布基盤) を自前スクリプトで書き直す選択は、上流が動くたびに追いかける負担を継続して負う。追い続ける前提が立たないなら、余計な差分を捨てて既製品の形に寄せる
- **技術選定は (a) テストが書ける (b) ユーザーが読める (c) 環境構築と実装が簡単、で選ぶ**。機能の優位性だけで選ばない。ユーザーが読める言語かどうか不明なら確認する
