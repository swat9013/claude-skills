# 意図は側面ごとに置き場を書き分ける

意図には側面があり、それぞれ表現先が異なる。

| 意図の側面 | 表現先 |
|-----------|--------|
| 仕様 (WHAT) | テスト |
| 実現方法 (HOW) | コード自体 |
| 変更の動機・背景 (WHY: 変更単位) | コミットログ |
| 非自明な選択の理由 (WHY: 実装単位) | コメント (コード内) |
| 設計判断の理由と棄却した代替案 (WHY: 設計単位) | ADR (Nygard, 2011) |

- コメントには実装単位の WHY (非自明な制約・workaround の理由) を書き、WHAT を書かない (comments explain why, not what)。名前・シグネチャで読める WHAT を繰り返す docstring / コメントは書かず、今回触る箇所で見つけたら削除する — コードと食い違ったとき、誤った説明として残る。ただし生成ドキュメントや IDE の表示で docstring だけが読まれる公開 API では、WHAT の docstring も書く
- WHAT の反復とも非自明な WHY とも言い切れないコメントも、今回触る箇所にあり、消しても読み手がコードを誤読しないなら削除に倒す — 読み手の判断を助けないまま、保守の対象だけを増やす
- 歴史的経緯・変更履歴はコメント・docstring に持たず ADR / git log へ委ねる (追記型の履歴表は並行編集の conflict 源にもなる)
