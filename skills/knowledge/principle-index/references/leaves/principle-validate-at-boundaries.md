# 検証は境界に集める

- **検証・型の絞り込み・防御的なエラー処理は境界に置く** (CLI 引数・設定ファイル・外部 API・ネットワーク・永続化からの読み出し)。境界の内側では型を信頼し、同じ値を再検証しない
- **境界で生データをドメイン型へ変換する**。内側へ渡すのは検証済みのドメイン型だけにし、転送・保存・フレームワーク由来の表現を公開面へ素通しさせない
- **境界側は検証と変換だけの薄い配線に留める**。ドメインロジックを境界側へ置くと、どこまでが検証済みかの線が引けなくなる
- **判定は「この値は今まさに境界を越えているか?」**。越えていないなら、そこでの検証は冗長
- 深い呼び出し先で空値・未設定チェック (nil / null / None) が積み増されているのは、境界での検証不足の兆候として読む

失敗そのものの可視化 (fail fast / Design by Contract) は `principle-fail-loudly` が扱う。本原則は検査を**どこへ集めるか**を決める。
