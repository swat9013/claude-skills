# 名前は定着した語で意図を言い当てる (intention-revealing names)

- **名前は、指す対象が何であり何をするかを言い当てる語にする**。`Manager`・`handle`・`data` のように中身を語らない汎用語は、名前が約束する意味を持たない。言い当てる名前が出てこないなら、対象の設計がまだ曖昧な兆候として扱う
- **語を作る前に、その概念を一語で呼べる既存の語 (leading word — 分野で広く通じる用語や設計パターン名のように、事前学習の知識に定着した語) を探す**。leading word は一語で概念の知識を呼び出すので、短く使い回せ、定義を読んでいない読み手にも意味が通る。例: 「支払いに失敗した契約へ催促を送り、間を置いて再請求する一連の流れ」は、作語の「再請求フロー」ではなく `dunning` と呼ぶ
- **既知の語を当てるのは、その語の通常の意味が概念と一致し、同じ文書群やコードで既に別の概念を指していないときに限る**。一致は、その語だけで指す対象や読み手の振る舞いが概念に絞れるかで測る — 意味が概念より広い語は呼び出す知識が広く、読み手ごとに解釈が割れる。通常の意味は対象領域の分野での意味で測る — leading word はその語が定着した分野の知識を呼び出すので、分野が混ざると読み手は語ごとに違う分野の意味で読む。同じ概念を呼ぶ語が分野ごとに違うときはこの分野の語を選び、別の分野で別の意味に定着した語はずれる語として扱う
- **表記は、その概念が多く書かれてきた言語に合わせる**。英語起源の技術用語は原語で置き、初出に日本語を添える。日英どちらにも定着した語は、表記の指定がなければ原語に倒す。日本語にしか無い概念は日本語で置く。定着していないカタカナの音訳は、概念の知識を呼び出す学習事例が少ないので使わない
- **当てはまる既存の語が無いときに限り、語を作る**。作った語は事前学習の知識を呼び出せないので、定義だけで意味が通るように 1 か所で定義し、他の箇所では定義を言い換えずにそこを参照する
- **ドメイン概念は primitive や string のまま持ち回らず、名前を持つ小さな型にする** (Primitive Obsession を避ける) — 型の名前が値の意味を呼び出し側に伝える。その値を扱う箇所が 1 つだけなら primitive のまま残す
- **記号 (α/β/L-α/S-1 等) で概念や論点を呼ぶのは、その分野で定着した記法 (計算量の n など) のときだけにする**。即席の記号は何も呼び出さず、スコープが狭くても後から置き換える手間と漏れが残る
- **略号は、省略前の名前を 1 か所で先に定義してから、文脈が確実な場合のみ使う** — 省略前の名前を知らない読み手には、略号は何も呼び出さない
