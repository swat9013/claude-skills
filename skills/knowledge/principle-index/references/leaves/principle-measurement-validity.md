# 計測値は、何がそれを縛り、何を測ったかを説明できてから使う

- **当てるのは、判断を変える数値**: 向きを変える軸は、その数値で判断が変わるかどうか。計測の前に、どの判断にも使わないと決めた参考値には、縛るものの特定と別のものの除外を省いてよい — 省いた数値は、縛るものの代わりに参考値と明示して報告し、後から判断の根拠にしない
- **計測の前に、それで変わる判断を書く**: 判断を変える結果と noise floor を先に決める — 後から決めると、出た数値に合わせて判断が作られる。実行ごとのばらつきが効果より大きいなら、その計測では決めない
- **数値を縛るものを特定する**: 「なぜ期待した値にならないか」(例: 並列度を 2 倍にしてもスループットが 2 倍にならない) に、実行中に取った profile か counter で答える。コードを読んだ推測は、縛るものの特定に数えない
- **その数値が測りえた別のものを挙げ、証拠で 1 つずつ除く**: エラー・skip や cache で省かれた処理・走らなかったコード・調整していない比較相手・noise・影響しないほど小さい部分
- **判断を変える数値には、実行回数・ばらつき・縛るものを添える**: 数値だけでは、読み手が確かめ直せない
- **評価結果では、どの実行も課題を行ったか・差が試行やモデルをまたいで保たれるか・その場面が重要かを問う** — 課題を行わずに通った実行や、1 回の試行だけの差は、測りたい能力ではなく偶然や抜け道を測っている

`principle-coverage-as-floor` はカバレッジの数値をどう運用するかを決める。本原則は、それが答えない**計測値そのものが、測りたいものを測っているか**を決める。
