# シグネチャで意図を表現させる

- 振る舞いを切り替える boolean 引数 (flag argument — Fowler) は、呼び出し側がリテラルで切り替えを選ぶなら使わず、振る舞いごとに関数を分ける — `f(x, True)` からは何が切り替わるか読めない。呼び出し側が実行時の値を受け渡すだけのとき (設定値・test の parametrize) は、分けると分岐が呼び出し側へ移るだけなので引数のままでよい。`set_enabled(True)` のように値そのものとして渡す boolean も対象外
- オプショナル引数は、省略したときの既定が大半の呼び出しで正しいときだけ使う。呼び出しごとに選ぶべき値は必須にして、呼び出し側に意図を書かせる
- 常に一緒に渡る引数の組 (Data Clumps — Fowler) は 1 つの型にまとめる — 組が複数の関数を渡ると、組の中身が変わるたびにすべてのシグネチャを直すことになり、組が表す概念も名前が無いまま残る。型の名前が引数の意味を呼び出し側に伝える。その組を受け取る関数が 1 つだけなら、まとめずに引数のまま残す — まとめた型の定義と変換が、引数を並べる手間より重くなる
