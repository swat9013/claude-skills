# 再実行しても同じ終状態へ収束させる

- **状態を変える操作は 2 つの問いに答えられる形にする**: 「2 回続けて走ったらどうなるか」「前回がどの時点で落ちていてもどうなるか」。答えが「前回何が残っていたかによる」なら、収束させる調整段 (reconciliation) が足りていない
- **起動時に現状を走査して収束させる**: 古い残骸を掃除し、生きている資源は引き継ぐ。残骸か引き継ぎ対象かの判定は、作成順やタイムスタンプではなく、期待する終状態と内容が一致するかで行う
- **占有印 (lock file / lease) は保持者プロセスの生存で判定する**。持ち主が消えた印を人手で消してもらう前提にしない
- **失敗した仕事は再投入で回復させる**。手作業の巻き戻しを前提にした手順を置かない

再実行のたびに残骸を人が判断して片付ける設計は、`principle-operability-first` が求める運用性を運用者側の負債に置き換える。
