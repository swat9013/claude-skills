# 意図を側面ごとに書き分ける

意図には 4 側面があり、それぞれ表現先が異なる。

| 意図の側面 | 表現先 |
|-----------|--------|
| 仕様 (WHAT) | テスト |
| 実現方法 (HOW) | コード自体 |
| 変更の動機・背景 (WHY: 変更単位) | コミットログ |
| 非自明な選択の理由 (WHY: 実装単位) | コメント (コード内) |

- コメントを控える既定より、非自明な制約・workaround の WHY をコード内コメントに残す方を優先する。名前・シグネチャで自明な WHAT を docstring / コメントで反復しない
- 歴史的経緯・変更履歴は本文に持たず ADR / git log へ委ねる (追記型の履歴表は並行編集の conflict 源にもなる)
- コメントは「なくても成立するならノイズ」— 迷ったら削除に倒す
