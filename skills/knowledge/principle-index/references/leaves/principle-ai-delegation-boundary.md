# 委譲は AFK 境界で切る

- **委譲は AFK 境界 (AFK = away from keyboard、人が張り付かない状態) で切る**。自律実行させる前に「人間が張り付かずに進めてよい範囲」と「人間に返す範囲」を分ける。人間に返す判断は、目的・価値観・構造の方針そのものを変える判断、戻しにくく既存の規範からは選べないトレードオフの判断、人しか持たない入力 (好み・優先度・外部の事実) が要る判断の 3 つに限る。判断ではなく人手でしか進まない作業 (権限で塞がれた操作・人の資格情報が要る操作・物理的な手作業) も人間に返す。既存の規範 (規約・決定記録・原則) から決まる判断は、設計の選好が絡んでも境界の内側に入る。境界は判断の種類で引き、人間に返す件数の多寡では動かさない。境界を「設計判断か否か」だけで引くと、設計判断ではないが人手でしか解けない作業が宙に浮く
- **人間に返す判断は提示に留める**。人間に返す範囲の判断は勝手に確定せず、トレードオフを添えて提示し、確定はユーザーが行う
- **AFK の自律実行中、人間に返す範囲の外では自分で判断して進めるのを既定にする**。下した判断と理由は CL (PR / MR の説明文) に書いて残し、人間が事後に覆せるようにする。覆されたら、その判断を導いた規範の側を直す — 同じ種類の判断で同じ誤りを繰り返さず、人間が覆す手間が再発しない。人間に返す範囲に当たって問うときは、返答を待ち続けずに作業を止め、未解決点を issue へ返してよい (添えるものは次項の引き渡し形式に従う)
- **引き渡し形式まで決める**。人間に返すときは停止理由・そこまでに残した成果・次に人間が実行する手順の checklist を添える (無言の終了は失敗扱い)

許可と禁止をどう効かせるか (permission・sandbox・資格情報の権限) は `principle-blast-radius` が扱う。本原則は**どこまで委譲し、どこで人間に返すか**を決める。
