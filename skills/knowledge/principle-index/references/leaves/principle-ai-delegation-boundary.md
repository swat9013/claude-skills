# 委譲は AFK 境界で切る

- **委譲は AFK 境界 (AFK = away from keyboard、人が張り付かない状態) で切る**。自律実行させる前に「人間が張り付かずに進めてよい範囲」と「人間に返す範囲」を分ける。人間に返す判断は、目的・価値観・構造の方針そのものを変える判断、戻しにくく既存の規範からは選べないトレードオフの判断、人しか持たない入力 (好み・優先度・外部の事実) が要る判断の 3 つに限る。構造の方針の変更のうち書かれた規範 (設計文書・決定記録・規約・原則) のどれにも無いものと、好みは、取り消せるなら境界の内側に入る。取り消せるとは、既定 branch の変更単位 (CL) を revert すれば元に戻り、判断の中身が repo の外へ書き出したもの (利用者の環境への書き込み・公開物・tracker への投稿や操作) が残らないことを指す。CL を届けること自体が生む通知と、配布物の文面の変更は、残るものに数えない — revert も同じ経路で届く。取り消せる判断は、誤っても人が事後に覆す費用が、問うて待つ費用より小さい。規範に無い方針を境界の内側で決めるのは、その件の判断に限る。同じ種類の判断に効く一般則として規範に書き起こすことは、人間に返す。目的・価値観の変更、優先度、外部の事実は、取り消せても人間に返す。判断ではなく人手でしか進まない作業 (権限で塞がれた操作・人の資格情報が要る操作・物理的な手作業) も人間に返す。既存の規範 (規約・決定記録・原則) から決まる判断は、設計の選好が絡んでも境界の内側に入る。境界は判断の種類で引き、人間に返す件数の多寡では動かさない。境界を「設計判断か否か」だけで引くと、設計判断ではないが人手でしか解けない作業が宙に浮く
- **人間に返す判断は提示に留める**。人間に返す範囲の判断は勝手に確定せず、トレードオフを添えて提示し、確定はユーザーが行う
- **AFK の自律実行中、人間に返す範囲の外では自分で判断して進めるのを既定にする**。下した判断と理由は CL (PR / MR の説明文) に書いて残し、人間が事後に覆せるようにする。覆されたら、その判断を導いた規範の側を直す。規範の文面を直すか、読み手に届く経路を直すか、文面が言葉にした前提を問い直すかは `principle-root-cause-and-hierarchy-of-controls` の層で選ぶ — 同じ種類の判断で同じ誤りを繰り返さず、人間が覆す手間が再発しない。人間に返す範囲に当たって問うときは、返答を待ち続けずに作業を止め、未解決点を issue へ返してよい (添えるものは次項の引き渡し形式に従う)
- **引き渡し形式まで決める**。人間に返すときは停止理由・そこまでに残した成果・次に人間が実行する手順の checklist を添える (無言の終了は失敗扱い)

許可と禁止をどう効かせるか (permission・sandbox・資格情報の権限) は `principle-blast-radius` が扱う。本原則は**どこまで委譲し、どこで人間に返すか**を決める。
