# 委譲は禁止の積み増しではなく境界の設計で決める

- **AI-navigable codebase を積極目標にする**。AI に読みやすい構造・命名・ドキュメントは人にも読みやすい
- **人間に返す判断は提示に留める**。人間に返す範囲 (下の AFK 境界。AFK = away from keyboard、人が張り付かない状態) の判断は勝手に確定せず、トレードオフを添えて提示し、確定はユーザーが行う
- **自律実行の制御は選択肢を広げる方向で設計する**。禁止を積み増して制御を強めるのではなく、破壊的・不可逆な副作用を持つ操作だけを塞ぎ、リスクのない操作は許可して委譲範囲を広げる
- **禁止は操作の種類ではなく副作用の有無で切る**
- **副作用で切った禁止も、まず資格情報の権限範囲と隔離境界で実現する**。操作単位の禁止は保守コストが高いので、権限範囲と隔離で塞げない操作に限る。簡単な抜け道がある禁止は防御として数えず削除し、守る必要があるものは権限範囲か隔離で守る
- **拒否が頻出する操作は設計の摩擦の指標**。拒否で突き返して代替探索の往復を増やすのは、制御が効いているのではなく設計が失敗している状態
- **委譲は AFK 境界で切る**。自律実行させる前に「人間が張り付かずに進めてよい範囲」と「人間に返す範囲」を分ける。人間に返す判断は、目的・価値観・構造の方針そのものを変える判断、戻しにくく既存の規範からは選べないトレードオフの判断、人しか持たない入力 (好み・優先度・外部の事実) が要る判断の 3 つに限る。判断ではなく人手でしか進まない作業 (権限で塞がれた操作・人の資格情報が要る操作・物理的な手作業) も人間に返す。既存の規範 (規約・決定記録・原則) から決まる判断は、設計の選好が絡んでも境界の内側に入る。境界は判断の種類で引き、人間に返す件数の多寡では動かさない。境界を「設計判断か否か」だけで引くと、設計判断ではないが人手でしか解けない作業が宙に浮く
- **AFK の自律実行中、人間に返す範囲の外では自分で判断して進めるのを既定にする**。下した判断と理由は CL (PR / MR の説明文) に書いて残し、人間が事後に覆せるようにする。覆されたら、その判断を導いた規範の側を直す — 同じ種類の判断で同じ誤りを繰り返さず、人間が覆す手間が再発しない。人間に返す範囲に当たって問うときは、返答を待ち続けずに作業を止め、未解決点を issue へ返してよい (添えるものは次項の引き渡し形式に従う)
- **引き渡し形式まで決める**。人間に返すときは停止理由・そこまでに残した成果・次に人間が実行する手順の checklist を添える (無言の終了は失敗扱い)
