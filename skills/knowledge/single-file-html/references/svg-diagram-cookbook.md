# Inline-SVG Diagram Cookbook

Patterns for embedding diagrams as inline SVG in a single-file HTML page — zero dependencies, fully self-contained. All builders are **pure functions returning SVG strings**, which makes them unit-testable in Node (see bottom).

## Why pure string builders

- No CDN, no canvas, no runtime libs — the SVG is generated by plain JS in the page.
- Pure `(data) -> string` functions are testable headless: run them in Node and scan output for `NaN`/`undefined` before ever opening a browser.
- Data-driven: one data array + one dispatcher renders every figure consistently.

## Minimal toolkit

```js
const C = { ink:'#1f2733', mut:'#8a93a3', ln:'#cfd6e0',
            green:'#2f9e6f', block:'#d4493f' };

// NOTE: aria-hidden="true" here assumes a DECORATIVE figure whose meaning is
// repeated in adjacent text. If the SVG is the sole carrier of information
// (e.g. a status shape), drop aria-hidden and pass role="img" + aria-label="...".
const svg = inner =>
  `<svg class="dia" viewBox="0 0 300 88" xmlns="http://www.w3.org/2000/svg" role="img" aria-hidden="true">${inner}</svg>`;

const box = (x,y,w,h,label,fill,stroke,tc) =>
  `<rect x="${x}" y="${y}" width="${w}" height="${h}" rx="5" fill="${fill||'#fff'}" stroke="${stroke||C.ln}"/>` +
  (label ? `<text x="${x+w/2}" y="${y+h/2+3.4}" text-anchor="middle" font-size="9.5" fill="${tc||C.ink}">${label}</text>` : '');

const harrow = (x1,x2,y,color) => {           // horizontal arrow with head
  const d = x2 > x1 ? 1 : -1;
  return `<line x1="${x1}" y1="${y}" x2="${x2-6*d}" y2="${y}" stroke="${color}" stroke-width="1.5"/>` +
         `<path d="M ${x2} ${y} L ${x2-6*d} ${y-3.5} L ${x2-6*d} ${y+3.5} Z" fill="${color}"/>`;
};
```

CSS to make figures scale to their container. The colors come through the semantic tokens that the `frontend-refine` Prep phase writes into `.ai/design/design-tokens.css` (step 1 of the authoring workflow) — raw hex outside `:root` is a Red Flag in the static review that gates this skill:

```css
.dia { display:block; width:100%; height:auto; background:var(--muted);
       border:1px solid var(--border); border-radius:8px; }
```

## Data-driven dispatch

```js
const DIA = {
  boundary(){ /* return svg(...) */ },
  mapping(){ /* ... */ },
  // one method per figure kind
};
// map each data item to a builder
const FIG = { itemA:()=>DIA.boundary(), itemB:()=>DIA.mapping() };
// in the render loop:
card.innerHTML += (FIG[item.id] || (()=>''))();
```

## Example figures (compact)

**Mapping (A -> B, with a broken link):** show concrete correspondence; a missing target is red.

```js
mapping(){
  let g = `<text x="57" y="12" text-anchor="middle" font-size="8.5" fill="${C.mut}">source</text>`;
  [['/users','spec 1',1],['/new','(none)',0]].forEach((r,i)=>{
    const y=20+i*20, ok=r[2]===1;
    g += box(14,y,86,15,r[0]);
    if (ok){ g += box(206,y,86,15,r[1]) + harrow(100,206,y+7.5,C.green); }
    else   { g += box(206,y,86,15,r[1],'#fdecea',C.block,C.block) +
             `<line x1="100" y1="${y+7.5}" x2="200" y2="${y+7.5}" stroke="${C.block}" stroke-dasharray="4 3"/>`; }
  });
  return svg(g);
}
```

**Other useful kinds:** a *scan* (list of items, scanner glyph, one flagged red); a *gauge* (semicircle arc + needle for an observe-only metric); a *two-layer* diagram (downward = allowed, upward dashed red = violation). Build each to show its **specific mechanism**, not a generic chart reused everywhere.

## Diagram principles (apply to every figure)

1. **Shape carries the meaning.** If the information lives only in a text label, the figure failed. Geometry first, labels second.
2. **Specific over abstract.** Draw the real thing being depicted, not one reusable abstract chart for all items.
3. **Name by what it shows/detects**, not the tool/technique behind it.
4. **Cut decoration.** No count cards, no repeated captions, nothing that adds no information.

## Headless builder test (when builders compute coordinates)

Run this when any builder derives coordinates by arithmetic/loops/trig (where a typo can produce `NaN`); skip it for fully static markup. Builders are pure, so test them in Node without a DOM.

**Adapt the harness to your builder signature.** The snippet below assumes a `FIG` object of zero-arg builders. If your builders take arguments (e.g. `indicator(status)`), export that function instead and loop over its inputs:

```js
// for a builder like `const indicator = status => svg(...)`:
for (const s of ['ok','warn','down']) { const out = indicator(s); /* assert wrapper + no NaN/undefined */ }
```

The `FIG`-map variant — extract the builder block from the HTML and exercise every entry:

```js
// test-dia.mjs  —  node test-dia.mjs
import fs from 'node:fs';
const src = fs.readFileSync('page.html','utf8');
const a = src.indexOf('/* builders-start */');   // mark your block with comments
const b = src.indexOf('/* builders-end */');
const FIG = eval('(()=>{' + src.slice(a,b) + '\nreturn FIG;})()');
let ok = 0; const err = [];
for (const k of Object.keys(FIG)) {
  try {
    const s = FIG[k]();
    if (!s.startsWith('<svg') || !s.endsWith('</svg>')) throw new Error('bad wrapper');
    if (s.includes('NaN') || s.includes('undefined')) throw new Error('NaN/undefined');
    ok++;
  } catch (e) { err.push(k + ': ' + e.message); }
}
console.log('rendered OK:', ok, '/', Object.keys(FIG).length);
if (err.length) console.log('ERRORS:', JSON.stringify(err));
```

A coordinate typo that yields `NaN` in a path `d=""` renders as nothing in the browser — this catches it in milliseconds.
