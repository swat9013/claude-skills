# 呼び出し元向けの反映の契約

本 skill を invoke する呼び出し元 (他の skill でも、session から直接でも) が、承認済みの変更を書かせるときの呼び出し口。決めるのは、渡す args・invoke の回数・検証の範囲 (返された指摘の扱いを含む)・反映を終えられなかったときの返し方の 4 点だけ。何を書かせるか (候補・証拠・invoke 時に添える制約) と、反映の前後に呼び出し元が通す確認は、呼び出し元の手順が持つ。

## 渡す args

- 反映先が既存の file なら、その path 1 本を渡す
- まだ存在しない file を起こすなら `新規: <component> <目的>` を渡す。存在しない path を渡すと、本 skill の手順 1 が対象 file を解決できない
- args にはこの 2 形のどちらかだけを置く。反映する内容 (候補・証拠・反映案) と呼び出し元の制約は、invoke 直前の同一 turn のテキストで宣言する — 同じ context に載ったまま本 skill へ渡るので、args に足す必要はない
- no-op の削除を書かせるなら、呼び出し元が通した確認 (suite か micro-test) も同じ turn で宣言する。宣言の無い no-op の削除は、本 skill が書かずに報告へ回す

## invoke の回数

- 1 回の invoke で書き換わる範囲は本 skill の手順 1 の「書き換える対象は広げない」が決め、args の file を超えない (例外は外出しのパッチで、対象 skill の `references/` に新しい file が足されうる)。反映先 file 1 本につき 1 回 invoke する。2 file にまたがる変更 (移動先への追加と元 file の行削除など) は、file ごとに 1 回ずつ invoke する
- 新しい `.claude/rules/<topic>.md` を起こし、対象 repo の CLAUDE.md が rules の索引表を持つなら、CLAUDE.md を args にもう 1 回 invoke して索引行を足す。この 1 回を省くと、新しい rules が索引に載らないまま反映が終わる

## 検証の範囲

本 skill の検証の範囲は、invoke 直前の同じ turn のテキストで `全体` / `増分` / `省く` のどれかとして宣言する。宣言しなければ `全体` になる。本 skill は前の invoke を数えないので、同じ変更のまとまり (CL を切る運用ならその CL) の中で同じ file の検証がどこまで済んだかは呼び出し元が数える — 済んだ範囲を検証し直すと、反映した文が次の検証の指摘を呼び、検証が終わらない。段は `全体` → `増分` (再レビュー。検証 subagent だけを起動し、その invoke で変更した行と、それが他の行と食い違う箇所を見させる。構造 reviewer は起動しない) → `省く` の順に進め、その file でまだ終わっていない最初の段を宣言する。`<検証|構造>レビュー未実施:` 行を返した段と、その file を未レビューとして挙げた段は、終わった段に数えない。

本 skill が返す Consider は、直すかを呼び出し元が決める (人の判断が要るなら user に尋ねる)。採らないと決めた指摘は、同じ file を次に invoke する直前の turn で宣言する — 本 skill はそれを Noted に置く。Noted は呼び出し元の報告に記録として残す。

## 反映を終えられなかったとき

本 skill が反映を完了せずに終わったら、本 skill が返した停止理由と (あれば) 復旧の案内を、呼び出し元は自分の報告にそのまま載せる。反映を終えても検証が `<検証|構造>レビュー未実施:` 行・未レビューの file・構造提案の判断材料を欠いた file を返したときは、その行と file の一覧を同じように載せる。どちらも解釈も再記述もしない — 停止の検知と案内は本 skill が持つので、言い換えると復旧に要る情報が落ちる。
