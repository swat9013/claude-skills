# 呼び出し元向けの反映の契約

本 skill を invoke する呼び出し元 (他の skill でも、session から直接でも) が、承認済みの変更を書かせるときの呼び出し口。決めるのは、渡す args・invoke の回数・検証の範囲 (返された指摘の扱いを含む)・反映を終えられなかったときの返し方・委譲後の変更 path の照合の手順の 5 点だけ。照合を実行するのは呼び出し元で、許可する path と止めたときの記録先は呼び出し元の手順が決める。何を書かせるか (候補・証拠・invoke 時に添える制約) と、照合のほかに反映の前後で呼び出し元が通す確認も、呼び出し元の手順が持つ。

## 渡す args

- 反映先が既存の file なら、その path 1 本を渡す
- まだ存在しない file を起こすなら `新規: <component> <目的>` を渡す。存在しない path を渡すと、本 skill の手順 1 が対象 file を解決できない
- args にはこの 2 形のどちらかだけを置く。反映する内容 (候補・証拠・反映案) と呼び出し元の制約は、invoke 直前の同一 turn のテキストで宣言する — 同じ context に載ったまま本 skill へ渡るので、args に足す必要はない。渡す file が `SKILL.md`・`CLAUDE.md`・`rules/` 直下の `.md`・agent 定義・hook の設定とそれが指す script のどれでもない (skill の `references/` の file など) ときは、その component も同じ turn で宣言する。宣言が無いと、本 skill は分類外として止まる
- no-op の削除を書かせるなら、呼び出し元が通した確認 (suite か micro-test) も同じ turn で宣言する。宣言の無い no-op の削除は、本 skill が書かずに報告へ回す

## invoke の回数

- 1 回の invoke で書き換わる範囲は本 skill の手順 1 の「書き換える対象は広げない」が決め、args の file を超えない (例外は外出しのパッチで、対象 skill の `references/` に新しい file が足されうる)。反映先 file 1 本につき 1 回 invoke する。2 file にまたがる変更 (移動先への追加と元 file の行削除など) は、file ごとに 1 回ずつ invoke する
- 新しい `.claude/rules/<topic>.md` を起こし、対象 repo の CLAUDE.md が rules の索引表を持つなら、CLAUDE.md を args にもう 1 回 invoke して索引行を足す。この 1 回を省くと、新しい rules が索引に載らないまま反映が終わる

## 検証の範囲

本 skill は、宣言が無ければ invoke ごとにその invoke で診断した行を検証する (component の規範と、対象 file に当たる設計 doc に照らす)。検証を省くときだけ、invoke 直前の同じ turn のテキストで `省く` と宣言する。本 skill は前の invoke を数えないので、同じ変更のまとまり (CL を切る運用ならその CL) の中で同じ file を何回検証したかは呼び出し元が数える — 検証し直すたびに、反映した文が次の検証の指摘を呼び、検証が終わらない。同じ file の検証は 2 回 (初回と、その後の変更の再レビュー) までにし、3 回目からは `省く` を宣言する。検証 subagent の側が `検証レビュー未実施:` 行を返した回と、その file を未レビューとして挙げた回は、回数に数えない (構造 reviewer の側だけが未実施なら検証には数え、構造レビューは未レビューとして報告に載せる)。

同じ変更のまとまりで同じ component の file を複数書き、それらが同じ作業の中で一緒に読まれ (同じ索引から引かれる file・同じ skill の SKILL.md と `references/` など)、1 体が全 file を全文 Read して足りる量なら、検証を 1 組にまとめてよい — file ごとに起動すると、検証の質を変えずに費用だけが file の数に比例して増える。1 組に入れる file を書く invoke では `省く` を宣言し、全部を書き終えてから、本 skill の invoke で読み込まれた SKILL.md の手順 4 の起動条件で 1 組だけ起動する (構造 reviewer の条件は、1 組に入れた invoke のどれかのパッチが満たせば満たす)。それらの file はすべてレビュー対象に並べ、prompt の雛形・参照する reference・構造 reviewer に渡す harness 全体一覧の作り方は手順 4 のとおりにする。返った指摘は呼び出し元が手順 5 の区分で分け、Act on と、採った Consider は file ごとに本 skill を invoke して反映させる。この反映の invoke は手順 5 の反映に当たるので、検証し直さず `省く` を宣言する。

この 1 組はそれらの file の検証 1 回に数える。ただし数えない回の決め方は本節の最初の段落と同じで、数えない file は手順 5 と同じく未レビューとして報告に載せる。反映の invoke の `省く` は回数に数えないので、反映の後に同じ file を別の理由で直したら、2 回の上限に達していなければ宣言せずに検証する。まだ 1 回も検証していない file で `省く` を宣言してよいのは、1 組に入れる file を書く invoke と 1 組の指摘を反映する invoke だけで、1 組を起動しないまま終えると、それらの file は検証を通らずに残る。

本 skill が返す Consider は、直すかを呼び出し元が決める (人の判断が要るなら user に尋ねる)。理由が「方針の変更 — 人へ返す」の Consider (設計 doc の検査の指摘) は、呼び出し元が採否を決めずに user へ返す — 設計 doc を変えるかは人の決定なので。採らないと決めた指摘は、同じ file を次に invoke する直前の turn で宣言する — 本 skill はそれを Noted に置く。Noted は呼び出し元の報告に記録として残す。

## 反映を終えられなかったとき

本 skill が反映を完了せずに終わったら、本 skill が返した停止理由と (あれば) 復旧の案内を、呼び出し元は自分の報告にそのまま載せる。反映を終えても検証が `<検証|構造>レビュー未実施:` 行・理由が `設計 doc 不在` の `設計 skip:` 行 (宣言された設計 doc に照らせなかった file)・未レビューの file・構造提案の判断材料を欠いた file を返したときは、その行と file の一覧を同じように載せる。どちらも解釈も再記述もしない — 停止の検知と案内は本 skill が持つので、言い換えると復旧に要る情報が落ちる。

## 委譲後の変更 path の照合

本 skill は呼び出し元の許可 path (呼び出し元の手順が決める、invoke ごとに書いてよい path) を知らず、書いた path がそこに収まったかを返さない (返す diff とパッチの行は本 skill の申告にとどまる)。args の file の外 (外出しの新しい file・別の file) を書いたかは、許可 path を手順で決めている呼び出し元が、invoke ごとに git の事実で次の手順で確かめる。cwd と反映先の repo が違いうるときは、git をすべて `git -C <repo-root>` で撃ち、控えと照合を同じ repo に対して行う:

1. invoke の直前に `git rev-parse HEAD` と `git status --porcelain --untracked-files=all` の出力を控え、status に載っていた path (前の invoke で書いた file を含む) ごとに `git hash-object <path>` の値も控える (file が無い path は「不在」と控える)
2. 戻ったら (反映を完了したかを問わず) `git diff --name-only <控えた HEAD>` と `git status --porcelain --untracked-files=all` の path を合わせる。控えた status に載っていた path は、`git hash-object` の値が控えと変わっていない (file が消えていない) もの (「不在」と控えた path は戻った後も不在のもの) だけを除く — 前の invoke で書いた file や元から未 commit の変更があった file への範囲外の書き込みを見逃さないため。`--untracked-files=all` は、新規ディレクトリの中の file が `?? <dir>/` に畳まれて許可 path と一致しなくなるのを防ぐ
3. 残った path を許可 path と比べる。git の出力は repo root 相対なので、許可 path も repo root 相対で比べる (args に渡した絶対 path と比べると全件が対象外に見える)。許可 path の外にある新規 file も対象外とする

同じ file の中の差分が渡した制約に沿うかは path では確かめられないので、この照合の外にある。

対象外の path が 1 本でもあれば、反映をそこで止め、呼び出し元の先の工程へ進まない。委譲先が意図して書いた変更か事故かは判定できないので、対象外の path は元に戻さず判断を人間へ返す。呼び出し元の手順が決めた記録先に次を残す:

- 対象外の path の一覧 (逐語)
- 止めた候補と、まだ invoke していない残りの候補 (承認済み・未反映として)
- 次に人間が行う手順: 対象外の path の差分を確認して残すか破棄するかを決める。止めた候補の許可 path に差分が出ていれば、それも残すか破棄するかを決める (残したまま再 invoke すると同じ差分を二重に書くので、残すならその候補は再 invoke から外す)。決めた後に未反映の候補を再 invoke する。1 つの候補を file ごとに複数回 invoke する (「invoke の回数」の 2 file にまたがる変更) 途中で止めたときは、同じ候補の前の invoke で書いた file も確認の対象に並べ、その候補で再 invoke するのは、残すと決めた file を除いた、まだ照合を通っていない file の invoke だけにする
