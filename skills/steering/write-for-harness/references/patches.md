# パッチの選び方

指示文への 1 回の変更を**パッチ**と呼ぶ。指示文を変えるときは、下の 6 種を同列の候補として並べ、対象の行ごとに診断表で選ぶ。追加を既定に置くと、変えるたびに本文が増えていく。

## 6 種

| 種別 | 何をするか | 編集してよい範囲 |
|---|---|---|
| 追加 | 新しい項目を足す。既存の概念へ吸収できないときに限る — 観測した逸脱を起こした既存の概念を先に特定し、それを直せば逸脱した場面の振る舞いが導けるなら、追加ではなく書き換えにする | 対象 file の中 |
| 書き換え | 既存の項目の文面を変える (強い語に替える・肯定の形にする・完了条件にする等)。強い語とは、事前学習の知識で振る舞いと結びついて定着した語のことで、強調語や MUST を足すことではない。粒度は下の「書き換えの粒度」に従う | 対象 file の中 |
| 削除 | 項目を消す | 対象 file の中。他 file にまたがる削除は報告だけにする |
| 統合 | 同じ概念を言い直している複数の項目を 1 つにまとめる | 対象 file の中。他 file にまたがる統合は報告だけにする |
| 外出し | 一部の分岐でしか要らない内容を、本文から `references/` の file へ移し、本文には読む条件を書いた参照だけを残す。読まれる分岐でしか context に載らないので、毎ターンの load は増えない | 対象 skill の dir 配下の `references/` に**新しく作る** file だけ。既存の別 file への移動と、`references/` を持たない component (CLAUDE.md・rules・hook 注入文・agent 定義) での外出しは報告だけにする |
| 分割 | 規律を、独立して呼べる skill として切り出す。切り出した skill の description が毎ターンの load になる代わりに、他の skill からも呼べる | 編集しない。報告に、切り出す範囲と、その skill の leading word を書く |

報告だけにしたパッチは編集せず、案として呼び出し元へ報告する。

新しく file を作るときは、診断する既存の行が無いので、追加と外出しの判断だけを当てる。

## 書き換えの粒度

評価 suite (skill の振る舞いを変更の前後で比べられる評価ケースの集合) がある skill だけ、節単位の書き換えを許す。suite の無い skill は、項目単位の差分 (削除・統合・1 文への言い換え) に限る — 振る舞いが変わっていないことを確かめる手段が無いまま節を書き直すと、どの規範が抜けたかが誰にも見えない。skill 以外の component は suite を持たないので、常に項目単位に限る。

suite の有無は、skill が属する plugin の root にある `evals/<skill 名>/` で判定する。その下に `case.yaml` か `prompt.md` を持つ dir が 1 つ以上あれば suite がある。無ければ suite の無い skill として扱う。

## 診断表

| 行の分類 | パッチ |
|---|---|
| 振る舞いの規範。既知の語彙を強い表記で書いている | 残す。同じ概念を複数の行で言い直していれば、1 語に統合する |
| 振る舞いの規範。既知の語彙だが、表記が弱い (定着していない音訳など) か、語そのものが弱い (thorough など) | 書き換え。原語、または強い語にする |
| 振る舞いの規範。repo で作った語彙を使っている | 残す。定義が散らばっていれば 1 箇所にまとめる (統合) |
| 禁止の形で書かれた規範 | 書き換え。肯定の形にする。肯定の形で書けない hard guardrail は、目標の行動と対にして残す |
| 手順を並べることで作業量を決めている | 書き換え。完了条件にする |
| 事実で、どの分岐でも要る | 残す |
| 事実で、一部の分岐でしか要らない | 外出し (`references/` へ) |
| 事実で、環境を見れば分かる | 削除。環境から引かせる |
| 既定どおりの行 (no-op) | 削除。eval suite がある skill は suite で、無い skill は「その行あり / なし」の subagent micro-test で、挙動が変わらないと確かめたものだけ |
| 独立した leading word を持つ規律、またはほかの skill からも要る規律 | 分割。報告だけにする |
| 既存の skill の内容を本文に書き直している | 統合。その skill の呼び出しに置き換える。報告だけにする |

既存の skill の内容を書き直している行を報告だけにするのは、置き換え先の skill が呼び出せるか (model から起動できるか) と、呼び出し先との対の明文化を確かめてから決めるため。
