# パッチの選び方

指示文への 1 回の変更を**パッチ**と呼ぶ。指示文を変えるときは、下の 6 種を同列の候補として並べ、対象の行ごとに診断表で選ぶ。追加を既定に置くと、変えるたびに本文が増えていく。

## 6 種

| 種別 | 何をするか | 編集してよい範囲 |
|---|---|---|
| 追加 | 新しい項目を足す。既存の概念へ吸収できないときに限る — 観測した逸脱を起こした既存の概念を先に特定し、それを直せば逸脱した場面の振る舞いが導けるなら、追加ではなく書き換えにする | 対象 file の中 |
| 書き換え | 既存の項目の文面を変える (強い語に替える・肯定の形にする・完了条件にする等)。強い語とは、事前学習の知識で振る舞いと結びついて定着した語のことで、強調語や MUST を足すことではない。粒度は下の「書き換えの粒度」に従う | 対象 file の中 |
| 削除 | 項目を消す | 対象 file の中。他 file にまたがる削除は報告だけにする |
| 統合 | 同じ概念を言い直している複数の項目を 1 つにまとめる | 対象 file の中。他 file にまたがる統合は報告だけにする |
| 外出し | 一部の分岐でしか要らない内容を、本文から `references/` の file へ移し、本文には読む条件を書いた参照だけを残す。読まれる分岐でしか context に載らないので、毎ターンの load は増えない | 対象 skill の dir 配下の `references/` に**新しく作る** file だけ。既存の別 file への移動と、`references/` を持たない component (CLAUDE.md・rules・hook 注入文・agent 定義) での外出しは報告だけにする |
| 分割 | 規律を、独立して呼べる skill として切り出す。切り出した skill の description が毎ターンの load になる代わりに、他の skill からも呼べる | 編集しない。報告に、切り出す範囲と、その skill の trigger 語を書く |

報告だけにしたパッチは編集せず、案として呼び出し元へ報告する。宣言された変更そのものが報告だけのパッチに当たったときの返し方は、SKILL.md 手順 5 の「反映を終えられなかったとき」に従う。

新しく file を作るときは、診断する既存の行が無いので、追加と外出しの判断だけを当てる。

## 書き換えの粒度

評価 suite (skill の振る舞いを変更の前後で比べられる評価ケースの集合) がある skill だけ、節単位の書き換えを許す。suite の無い skill は、項目単位の差分 (削除・統合・1 文への言い換え) に限る — 振る舞いが変わっていないことを確かめる手段が無いまま節を書き直すと、どの規範が抜けたかが誰にも見えない。skill 以外の component は suite を持たないので、常に項目単位に限る。

suite の有無は、skill が属する plugin の root にある `evals/<skill 名>/` で判定する。その下に `case.yaml` か `prompt.md` を持つ dir が 1 つ以上あれば suite がある。無ければ suite の無い skill として扱う。

## 診断表

| 行の分類 | パッチ |
|---|---|

| <a id="diag-weak-wording"></a>振る舞いの規範。既知の語彙だが、表記が弱い (定着していない音訳など) か、語そのものが弱い (thorough など) | 書き換え。原語、または強い語にする |
| <a id="diag-repo-vocabulary"></a>振る舞いの規範。repo で作った語彙を使っている | 残す。<a id="diag-scattered-definition"></a>定義が散らばっていれば 1 箇所にまとめる (統合) |
| <a id="diag-prohibition"></a>禁止の形で書かれた規範 | 書き換え。肯定の形にする。肯定の形で書けない hard guardrail は、目標の行動と対にして残す |
| <a id="diag-procedure-list"></a>手順を並べることで作業量を決めている | 書き換え。完了条件にする |
| <a id="diag-fact-every-branch"></a>事実で、どの分岐でも要る | 残す |
| <a id="diag-fact-some-branches"></a>事実で、一部の分岐でしか要らない | 外出し (`references/` へ) |
| <a id="diag-fact-from-environment"></a>事実で、環境を見れば分かる | 削除。環境から引かせる |
| <a id="diag-no-op"></a>既定どおりの行 (no-op) | 削除。eval suite がある skill は下の「no-op の suite 検証」で、それ以外 (suite の無い skill と skill 以外の component) は下の「no-op の micro-test」で、挙動が変わらないと確かめたものだけ |

| <a id="diag-existing-skill-copy"></a>既存の skill の内容を本文に書き直している | 統合。その skill の呼び出しに置き換える。報告だけにする — 置き換え先の skill が呼び出せるか (model から起動できるか) と、呼び出し先との対の明文化を確かめてから決めるため |

## no-op の suite 検証

no-op の候補をまとめて、評価 suite で現行版と比べる。比べる版は、対象 skill が属する plugin root ごと (suite・同梱の agent ごと) に作る — suite は plugin root の `evals/` にあるので、file 単体の版は実行器に渡せない。評価の実行器に渡す plugin の path を、現行の plugin root と比べる版に替えて走らせる。

- **走らせ方**: どの版も同じ suite を同じ model で、skill を入れた状態だけで走らせる (`claude plugin eval` なら `--ablation none`) — skill あり / なしを並べて走らせると、skill を呼ぶべき case で skill が起動したかが採点から外れる
- **幅**: 現行版は 3 回走らせ、case ごとの score の最小〜最大をその case のばらつきの幅にする — 各版 1 回の run からは幅が得られない。実行器が 1 回の run の中で case ごとに複数回試行するなら、3 回の run の代わりに、現行版 1 回の run の試行の幅 (実行器が幅を出さなければ、試行ごとの score の最小〜最大) を使ってよい
- **比べる版**: 候補を全部消した版と、下の確かめ直しで作る 1 件ずつ戻した版・残した候補をまとめて消した版は 1 回ずつ走らせ、case の score が幅の中にあれば「収まる」とする (試行から得た幅を使うときは、その版の試行ごとの score が全部幅の中にあれば収まる — 試行の平均を試行の幅と比べると、外れた試行が平均に埋もれる)
- **確かめ直し**: 全 case が収まれば全件を候補に残す。幅を超えた case があれば、候補を 1 件ずつ戻した版でその case を走らせ直し、その case を幅に収めた候補 (= 差を生んでいた候補) を落とす。落とした後は、残した候補をまとめて消した版でもう 1 度走らせる (組み合わせで出る差は 1 件ずつ戻しても消えない)。落とした候補が無ければ、全部消した版の run をこの版の run とする — 同じ版を走らせ直して偶然幅に収まった run を、確かめたことに数えない
- **判定**: no-op として削除に回せるのは、最後に走らせた版が全 case で幅に収まったときの残した候補だけ。最後の run で幅を超えた case が残ったとき、または suite を走らせられないときは、no-op 候補を全部未検証にし、削除に回さない

## no-op の micro-test

no-op の候補の行 1 つにつき、Agent tool で subagent を 2 体、同じ message で起動し、「その行あり / なし」で振る舞いが変わるかを比べる。

- **かける候補**: 1 回の実行で、est_tokens (候補の現行の文面の推定 token 数。推定値を持たない呼び出し元は文面の文字数 (`wc -m`) で代える — 選ぶ順を決めるだけなので、文字数の順で足りる) の降順に上位 5 件までにする — 候補 1 件につき 2 体を起動するので、上限が無いと no-op の疑いが多い対象で起動数が際限なく増える。上限から外れた候補は確かめていないので削除に回さず、呼び出し元の報告で未検証として扱う
- **subagent の種類とモデル**: CLAUDE.md 系を自動で読まない種類 (built-in の `Explore` など) を、Agent tool の `model` 引数で呼び出し元のセッションと同じモデルに明示して使う — built-in の種類は既定のモデルがセッションと違いうるので、継承に任せない。両側を同じ種類・同じモデルにそろえる。CLAUDE.md 系を自動で読む種類では、cwd の指示文が両側に載り、比べたい行の効き目がそれに紛れる。軽いモデルで比べても、その行を実際に読むモデルにとって no-op だという証拠にならない
- **prompt**: 2 体とも同じ場面と同じ問い (「この指示文の下で、次の場面をどう進めるか」) にし、違いは埋め込む指示文だけにする — 「あり」側は対象の本文、「なし」側はその本文から候補の行を除いたもの。tool で変更はさせず、どう進めるかを答えさせる
- **場面**: その行が効くなら振る舞いが分かれるものを組む。どちらの側でも同じ答えになる場面では、変わらなかったことが no-op の証拠にならない
- **判定**: 取る行動 (最初の行動・扱う範囲・止まるかどうか) で比べ、言い回しの違いは差に数えない。取る行動が一致したら「変わらない」とし、その候補を no-op として削除に回せる。違えば候補から落とす
