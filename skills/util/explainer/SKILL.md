# explainer — 図を中心にした HTML で説明する

会話の現在の話題を、結論を最初に置き、図を中心にした使い捨ての HTML 1 file で説明し、開いて見せる。起動した人は text では足りないと判断済みなので、text の図で代えずに HTML を作る。残したい知見の記録と、製品の画面の検査は扱わない。

## 1. 結論と主張を決める

対象は会話の現在の話題で、種類 (事象・状態・概念) を問わない。引数があれば、説明する対象か範囲の指定として読み、会話の話題と食い違えば引数を優先する。引数も会話の話題も無く対象が決まらなければ、作る前に何を説明するかを人に問う。

- 結論を 1 つに決め、それを支える主張を並べる。図は主張 1 つにつき 1 つ描く — 1 つの図に複数の主張を載せると、読み手はどれを読み取ればよいかを自分で探すことになる
- 主張を、確かめた事実 (この session の tool の結果・読んだ file に根拠があるもの) と推測に分ける。人の発言は、人がそう言ったという事実として扱い、発言の中身は tool の結果か file で確かめるまで推測に置く。根拠を示せない主張は推測に置く
- 図と本文に出す名前 (path・識別子・label) は実際のものを使う。作った例に置き換えると、読み手が手元の対象と照らせない

## 2. HTML を書く

一時ディレクトリに 1 file で書く。session が作業中の repo の外に一時 file の置き場を指定していればそこに、無ければ OS の一時ディレクトリに新しいディレクトリを作って置く。作業中の repo には書き込まない — 使い捨ての file が repo の差分に混ざる。

CSS・SVG・script はすべて file の中に書き、外部から読み込むもの (CDN の library・web font・外部の画像) を持たせない — network を制限した環境でも同じ見た目で開ける。

**図の描き方**は、主張の形で選ぶ。

| 主張の形 | 描き方 |
|---|---|
| 流れ・関係・状態の遷移・構成 | inline SVG |
| 比較・時系列・前後 | HTML/CSS の layout |
| 行の多い対照 | table |

既定は、操作の無い静的な page 1 つにする。step 再生などの操作は、経緯や手順を順に追う内容のときだけ入れる。

**内容**

- 最初の画面 (scroll する前に見える範囲) に結論を置く
- 確かめた事実と推測を見た目で区別し、どの見た目がどちらかを凡例で示す

**見た目**

- light と dark の両方で読める (`prefers-color-scheme`)
- 状態は色に加えて形か label でも表す — 色だけでは、色の見分けにくい読み手と白黒の表示に伝わらない
- 狭い幅でも横 scroll が出ない
- 次の定型を使わない: purple gradient、一律の角丸 card の並び、順序の無いものへの連番、emoji の marker、全部中央揃え

読み手の前提知識と見た目の好みは、session に載っている利用者の指示 (利用者の `CLAUDE.md`・output style など) に従い、上の「見た目」と食い違えば利用者の指示を優先する。指示が無ければ、読み手はこの会話の相手で、会話に出た知識を持つとし、会話の言語で書く。

## 3. checklist を当てる

開く前に次の checklist を HTML に当て、外れた項目は直す。

1. 最初の画面に結論がある
2. 各図の主張が 1 つで、図中の名前が実在する
3. 確かめた事実と推測が見分けられる
4. 文字の切れ・重なりが無い (狭い幅を含む)
5. 外部依存が無い

## 4. 開いて見せる

開き方は、試した結果を見て次の段へ進む。環境を推定して先の段へ飛ばない — 推定が外れると、開ける環境で path を返すだけになるか、要らない公開に進む。

1. OS の既定の方法で file を開くのを 1 回試みる
2. 開く操作が失敗し、tool 一覧に host (Claude Code) 組み込みの、HTML の page を公開する tool (Artifact tool) があれば、それで公開する。MCP server の公開の tool は使わない — 送り先が利用者の想定の外へ広がる。page の決まりはその tool の指示に従い、指示が求める範囲で HTML を直す。直したら、直した HTML に手順 3 の checklist を当て直す。公開したことと link を人に伝える
3. 公開する tool が無いか、公開できなければ、file の path を人に伝える。公開の tool を呼んだのに公開できたかを確かめられなかったときは、送った可能性があることと送ろうとした先も伝える

## 5. 報告する

報告には、file の path、開き方のどの段で終えたか (開く操作が通った・公開した link・path を伝えた)、checklist の項目ごとの結果を載せる。checklist の結果は、人に見せた版の HTML のものにする。開く操作が通っただけでは人の画面に出たかは分からないので、「開いた」と言い切らずに表示は未確認と書く。描画した画面を見て確かめられなかった項目は、通ったと書かずに「表示は未確認」のように未確認と書く — source を読んだだけでは、切れと重なりは分からない。
