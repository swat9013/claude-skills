# follow-up issue の起票の節

対象 repo の `docs/agents/issue-tracker.md` に置く「follow-up issue の起票」節の正本。作業の中で見つけた範囲外の欠陥・指摘を、どう issue にするかを決める。

雛形の箇条は 2 種に分かれる。太字の見出し語 (**変更した単位**・**直す**・**単位の外**) で始まる 3 つは、何を直し何を起票するかの基準で、repo が決める (雛形の文面は既定の値)。残りの箇条は、どの基準の下でも同じに振る舞う起票の手続きで、plugin が固定する。

## 雛形

文書の末尾に、次の節をそのまま置く。

```markdown
## follow-up issue の起票

作業の中で見つけた範囲外の欠陥・指摘を issue にするときは、次に従う。

- **変更した単位**: 変更した file と一緒に保守・レビューされるまとまり。skill なら skill のディレクトリ、それ以外は変更した file とその test
- **直す**: この CL の変更が生んだものと、単位の中で見つけたもの (レビューの区分を問わない)。ただし 1 CL で直せない大きさのものと `[上限超過]` は起票する (上限は、修正の差分を再レビュー 1 巡で見切れる量に保つためにある)。依頼や issue 本文が範囲を狭めているときはそれに従う
- **単位の外**: 欠陥 (条件次第で誤った挙動か誤った誘導を起こすもの) は起票し、欠陥を伴わない改善は起票せず CL の説明文に 1 行残す。どちらに当たるかは、レビューが指摘に付けた区分ではなく中身で決める
- 判定条件が同じで対象だけ違う指摘は 1 件に束ね、対象を本文の checklist に並べる
- 起票の前に、同じ指摘の issue を、open なものと、`docs/agents/triage-labels.md` の表で `wontfix` の役を持つ label で close したものから、題名と変更対象の file path の 2 通りで探す。当たった issue は本文を読み、判定条件と対象が同じかで同じ指摘かを決める。同じ指摘の issue があれば起票せず、open なら発端の issue と CL の番号があればコメントで足す
- 本文に `## 範囲` の節を置き、変更してよい範囲を、issue が直す file の「変更した単位」で書く。狭めるなら理由を書く。あわせて「範囲外で見つけた欠陥・指摘は `docs/agents/issue-tracker.md`「follow-up issue の起票」に従って扱う」を書く
- `## 範囲` の節の直前に、発端の issue (作業が担当している issue) を指す独立した 1 行 `発端: #<番号>` を置く。follow-up issue がどの作業から起票されたかを後から辿るための行で、着手可の判定には使わない。issue を介さず人が始めた作業には指す issue が無いので、行を置かない
- 付ける label は `docs/agents/triage-labels.md` の表で `needs-triage` の役を持つ label だけにする。`ready-for-agent` の役を持つ label は triage が付ける
```

## 突き合わせ (節が既にあるとき)

節 (見出しから次の同レベル以上の見出しの直前まで) の手続きの箇条を、雛形の手続きの箇条と 1 項目ずつ比べる。空行は照合せず、折り返しは連結して比べる。雛形に無い箇条 (repo が足した補足) は差分に数えない。雛形の手続きの箇条が欠けているか文面が違えば、その箇条の差分を変更提案として示す。基準の箇条は文面を比べない — 比べると、repo が決めた基準を雛形の既定の値へ戻す提案を毎回出す。基準の見出し語で始まる箇条が節に無いときだけ、雛形のその箇条を足すことを変更提案として示す。断られた差分は書き換えず、再実行のたびに同じ提案として示す (repo が意図して書き換えた箇条を残すかは、そのたびに利用者が決める)。

起票した issue を発端の issue の子 (tracker の親子の機能) にするよう指示する箇条 (「発端の issue」と「tracker の親子の機能」の両方を含む) は、補足とは数えず、削除を変更提案として示す — 「`発端: #<番号>`」の箇条と逆を指示する。
