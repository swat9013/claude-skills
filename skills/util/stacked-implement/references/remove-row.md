# 行を外す計画での後続の直し方

SKILL.md 手順 5 の「計画の修正」で行を外すときと、「最終報告」の項で `見送り` の行を外す行として扱うとき、提示の前に、計画に残す後続 (外す行を依存先にしている行のうち見送りでない行) を次のとおり直す。

- 依存先から外す行を除き、外す行の依存先と、外す行の成果を代わりに満たす行を加える (加えた行も外す行なら、同じく辿る) — 起動済みの後続の branch は外す行の依存先の差分を含む。成果を満たす行の「後続の前提」にこの後続の要るものを足す — 足さないと、その行から起動の合図が来ない。直した依存先を SKILL.md 手順 3 の計画の記録に書いたら、`${CLAUDE_SKILL_DIR}/scripts/cl-plan.py retarget <計画の記録> --remove <外す行の名前>... --done <CL が merged か closed の行の名前>...` (`${CLAUDE_SKILL_DIR}` は SKILL.md と同じ skill ディレクトリ) が出す `changes` の `to` へ、その行の分岐元と target (`base_branch` と `target`) を置き換える。`choose` に挙がった行は、候補から SKILL.md 手順 2 の規則で 1 つを選び、選ばなかった候補を `merge_in` に入れる。どの行の `merge_in` からも外す行の branch を除く — 外す行の branch のままだと、merge しても変更は既定ブランチに届かない
- 前項で分岐元と target を置き換えた後続のうち CL を出した行は、その CL を draft に戻し (`gh pr ready <番号> -R <CL の repo> --undo` / `glab mr update <番号> -R <CL の repo> --draft`)、直した計画を送る SendMessage で、その CL エージェントへ、CL の base を新しい target へ付け替えてから CL エージェント定義の「手順 2 の通し直し」を、保存したレビュー出力を使わずに全差分で走らせ直すよう指示する — 付け替えると外す行の commit が CL の差分に入るが、後続のレビューは外す行の branch を base にしたので、その commit はどのレビューも通っていない。その CL は、SKILL.md 手順 5 の「最終報告」の項で付け替えの後のレビュー出力を確かめるまで CL 到達に数えず、merge の判断へ進めない
- 後続の前提が外す行の成果そのもので、直した計画のどの行も満たさないなら、後続も外すか、その成果を後続の担当範囲へ移して後続の CL に載せるかを、推奨を付けて AskUserQuestion で問う — 要る成果の行き先は計画から決まらない。SKILL.md 手順 5 の「最終報告」の項の「止めない」は載せる答えに当たるので、問い直さない。載せると決めたら、外す行の issue を後続の行の issue 参照へ `Refs <issue 置き場>#<N>` で足し、CL の説明文にも足させる — 成果をどこまで移したかは読めないので、close はユーザーに任せる。載せると決めた起動済みの後続が、branch に残る外す行の commit を `返事待ち` で挙げてきたら、残すと返す
